# Architecture A (Claude) — written before reading Codex's Architecture B

## 1. Concept comparison (1–5)

| Criterion | Print intake + preflight | Proof/revision approval | Release triage | Support workbench |
|---|---|---|---|---|
| 30-second wow | 5 (artwork appears with a traced cut line already drawn) | 3 | 2 | 3 |
| Truly non-chat | 5 | 4 | 4 | 2 (support is conversational by nature; chatbot-adjacent) |
| Real inference opportunity | 4 (geometry + alpha + text + quantity + media) | 3 | 4 | 4 |
| Useful proactive action | 5 (a real production PDF with a CutContour spot stroke) | 3 | 3 | 3 |
| Wrong-guess recovery | 5 (sticker vs poster changes the whole job) | 3 | 3 | 3 |
| Side-by-side | 5 (multi-tab preflight/RIP panels vs one decision) | 3 | 3 | 3 |
| Realistic data | 4 (synthetic files generated by code, real geometry) | 3 | 4 | 3 |
| Feasibility | 3 (PDF render/analysis in pure Node is the hard part) | 4 | 4 | 4 |
| Lasting usefulness | 4 (owner's domain; a real shop pain) | 3 | 3 | 3 |
| **Total** | **40** | 29 | 30 | 28 |

Winner: print intake + preflight. The other three are weaker on visual proof and on how much a wrong guess changes the work.

## 2. Names
- PRESSENSE: "press" + "sense". Risk: reads like "presence", and may collide.
- MAKEREADY: the print term for preparing a press for a job, which is exactly what the system does. Risk: "MakeReady" is used by property-turnover software.
- KEYLINE: the line that defines the cut. Risk: a common company name.
- INREGISTER: "in register" means aligned. Clumsy.

Tagline: "The next decision, not another dashboard."

## 3. Architecture A

**Operator:** the prepress operator at a small print shop who receives customer files for roll-fed stickers, labels and posters.

**Screen states, one at a time:**
1. Arrival: a job lands. The artwork fills the canvas.
2. Reading: the real analysis steps appear as they finish (page boxes, render, alpha, inference).
3. Decision: one card. It shows what the system found, why it matters, what it prepared, and how sure it is.
4. Review: a before/after slider. The "after" is a server render of the generated PDF, not a mock.
5. Released: the artifact plus its verification checks.

A thin job strip is the only queue view. Evidence opens in a drawer only on request.

**Pipeline:** each stage writes a typed record.
- Intake: a file plus partial fields (qty, size, media, notes, all optional).
- Inspect: pdf-lib reads boxes, page count and spot-colour resources. pdf.js with @napi-rs/canvas renders an alpha mask and builds the operator list, which gives image PPI and the vector-vs-raster ratio. PNG/JPEG decode via canvas; DPI from pHYs/JFIF.
- Features: about 40 named features, from geometry, alpha shape, components, rectangularity, size, qty, media, cut-spot presence, and curated keyword groups from filename and notes (with simple negation). Filename and notes are separate features.
- Intent model: multinomial logistic regression over 4 intents (die-cut sticker, rectangular roll label, poster, banner). Trained offline on generator-produced real files. Held-out split is by generator family to avoid leakage. Temperature scaling on validation; ECE reported. Abstain when the calibrated top probability is under the threshold or the margin is small. Per-feature contributions (w·x) become the "evidence for / against" shown in the UI, so explanations come from the model itself.
- Session adaptation: an operator correction applies a bounded online update (a few SGD steps, max-norm delta) scoped to the session. Measured: does a near-duplicate job afterwards get the corrected intent?
- Decision selection: each intent has a check list. Each check is pass, fail or unknown, with severity and fixability. Priority order: critical unknown → fixable blocker → unfixable blocker → ready to release. One decision at a time, shown as "1 of N".
- Actions are prepared automatically:
  - sticker: a production PDF that embeds the source page (vectors preserved) plus a contour from alpha (dilate with a distance transform, marching squares, RDP), stroked in Separation /CutContour, tint 1, stroke-only, with overprint.
  - label: an N-up layout with a rectangular CutContour (a rectangle is exact here).
  - poster: scale to the requested size, with crop marks.
  - return-to-customer: a ticket with the reason.
  - Every action gets a roll arrangement estimate, honestly labelled as an estimate and not nesting.
- Approval gate: a proposal row holds sourceSha256, intent, action, canonical params, artifactSha256 and policyVersion. To approve, the client must echo proposalId and artifactSha256. The server compares them with the current, non-superseded proposal; anything stale gets a 409. A correction supersedes every open proposal of that job in one transaction.
- Execute: freeze the artifact, then verify it by re-parsing (CutContour separation present, stroke op used, dimensions within 0.1 mm), render it, and add a Ghostscript tiffsep check in CI. Only then mark it Released.
- Audit: an append-only, hash-chained event log per job.

**Persistence and hosting:** one Node 24 TS service. Postgres via `pg` in production and PGlite locally and in tests, so there is one SQL dialect. Artifacts are stored as bytea, so restarts keep them. Analysis runs in a worker_thread with resourceLimits and a timeout, one at a time.

**Security:**
- Upload limits: 10 MB, magic-byte checks, a page cap, a megapixel cap read before decode.
- pdf.js runs with isEvalSupported false. No filename ever becomes a path.
- Session cookie scoping on every query and download. Rate limits per IP, TTL purge.
- Notes are only tokenised into features; there is no LLM, so injection has nothing to command.

**Legacy comparison:** a representative multi-tab panel (File, Document, Preflight, Cut, Layout, Output) on the same backend and the same job. Interactions are counted in both modes by Playwright, using measured counts only.

**Wrong-guess scene:** "stickers-final.pdf" with an irregular transparent shape, no size, qty 1. The model leans to sticker, but not confidently, and prepares a contour PDF without releasing it. The operator clicks "Not this", sees the alternatives with their evidence, and picks Poster. The contour proposal is superseded, and the old approval now returns 409. The new decision is "Poster size? The art is 210×297 at 300 ppi; A1 would print at ~106 ppi", with A2 recommended. The new PDF is approved, released and verified. The audit log shows all of it.
